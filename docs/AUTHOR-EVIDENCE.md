# Author-focused evidence contract — stage 2 design proposal

**Approved interface; first metadata slice implemented.** Based on HEAD `8d3b1f6947667b9625bac2924abef86edef61c7e` plus existing dirty work on `brag-fast-test-loop`. The current source adds only CLI scope/identity resolution and streamed commit metadata/messages. Test/source expansion, lineage, helper context, authority and model work below remain proposals, not implemented capabilities. No legacy schema/default or execution authority changes. Go references mean `cmd/brag/<file>`.

## Implemented slice: `brag author-evidence`

Requires `--selected NAME=EMAIL`. `--all` and `--base REF` are mutually exclusive overrides; without either, read **Git config `brag.base`** (one value, with origin recorded). If absent, return an actionable noninteractive error requesting `--base`/configuration or explicit `--all`; never guess main/master or treat a remote-tracking upstream as parent. A base selects pinned `merge-base(ref,HEAD)..HEAD`, not HEAD alone or a proven branch-creation point; multiple/unrelated merge bases are errors. A configured HEAD boundary can validly yield zero commits. Target is HEAD only; overlay/dynamic/provider flags are rejected.

Output is `brag-author-evidence-v1`, method `brag-author-metadata-v1`: an intentionally **partial author-evidence report**, with separate `metadata.status` (`complete|partial`), exact-or-null scoped/selected totals, observed/retained/omitted counts, traversal-ID digest/endpoints, available tool build revision/dirty provenance (null if unavailable), raw/canonical identities, all parents, object/message hashes and typed untrusted message/subject/body. UTF-8 bytes are preserved; invalid UTF-8 is base64. Oversize message content is `not_retained`, with hash and unavailable coauthor inclusion; selected totals stay null when inclusion is incomplete. Authored and coauthored matches count once (`authored|coauthored|both`), with shared-credit claims explicitly distinguished. Parsed name/email fields are validated separately (names may contain `=`); only CLI NAME=EMAIL strings use separator parsing. Author, committer and coauthor evidence are independent: malformed/missing identity fields have `available:false`, explicit `unavailable_fields` reasons and lossless `unavailable_identity_headers` where present. Available message/real parents/provable selected matches remain retained, but incomplete metadata leaves selected totals null. `match_basis` reports proven matches only, not proof that unavailable fields lacked a match. `execution` is `not_run`; later evidence sections are `unavailable` / `not_collected`, even when all metadata is complete.

The first slice uses bounded 500-commit scheduling chunks, not a population cutoff; 1 MiB/commit object, 64 KiB/message, 256 MiB read commit-object contents, 5s/Git child and 5m overall context across metadata work. Rev-list drains first into a private, temporary, 64 MiB byte-bounded commit-ID spool outside the analyzed repository; only then do metadata chunks run, so consumer work does not consume rev-list's child deadline. The spool is removed on return; it stores IDs, not all objects or a persistent/resume cache. ID-storage failures produce partial/unknown totals. On every return, `metadata_omitted_commits` is exactly locally `enumerated_commits - inspected_commits` (complete inspections only), including IDs lost to spool flush/read failures. Incomplete records can still retain provable author evidence; error-event counts and shallow/unseen ancestry are not additional locally omitted commits. These Go read/retention limits **do not bound Git process peak memory**; reverse/topological enumeration's native memory envelope and motivating-repository runtime remain unmeasured.

Identity config is opened/read once with a ≤1 MiB + 1-byte detecting read bound, then only captured bytes are decoded. File identity/type/size/modification observations and path components are checked around reading. Relative paths cannot contain parent traversal; symlink files/directories are rejected independently of resolved containment, including explicit external absolute configs. Trusted resolved repository anchors and verified macOS `/var`/`/tmp` system-prefix aliases are distinguished from untrusted config-parent links. Darwin/Linux opens refuse a swapped final symlink and avoid blocking on a swapped FIFO; the other-platform fallback has regular-file observation checks but no equivalent nonblocking-open guarantee. This is not a race-proof filesystem sandbox; malicious concurrent namespace changes or blocking filesystem I/O are not comprehensively contained. Legacy config reading is untouched. Retention is separate: newest selected whole records in traversal order, ≤500 records / 8 MiB compact serialized record bytes (not an 8 MiB entire-report guarantee). `records` is currently an ordered array, not the later proposed ID map. Processing continues after retention fills; omissions remain explicit. Partial metadata preserves available records and null unknown totals. Shallow repositories retain locally available records but mark metadata partial with null complete totals and `shallow_boundary`; raw commit parent IDs remain intact, not fabricated roots. No fetching occurs. These starting limits are not motivating-repository performance guarantees. Existing tracked `.brag.json`, `--config`, `--identity` and `--alias` mappings are captured with effective-config digest and override provenance; there is no Git-user identity fallback. No source/test diff or model infrastructure is present.

## 1. Purpose and compatibility boundary

Deterministically gather evidence **about an explicitly selected author's work**, then let a model/human compare intended work, implementation and tested behavior. Center tests that the author introduced or changed and that have identifiable descendants/context on the target branch. Supply assertions/oracles, inputs, error/boundary branches and relevant implementation—not repository aggregates as proxies for personal quality. The collector never assigns quality, materiality, impact, rankings or a composite score. Static evidence enables source-based interpretation; it does not establish execution, coverage, defect detection or behavioral correctness.

Propose a separate `brag-author-evidence-v1` document and later `brag-author-projection-v1`; do not add fields to legacy schemas v1–v7 or change ordinary commands/default static output. The approved CLI is `brag author-evidence`; its first slice is described above. It must not require mutation/contribution execution. No automatic provider, network, tests, builds of analyzed code, generators, scanners or dependency resolution. Stage 1's short/full tests are unrelated to permission to execute an analyzed repository.

**Legacy/default output is not the proposed source-evidence contract:** repository-wide AST collection explicitly disclaims author attribution (`engineering.go:157–173`); report fields lack messages/diff hunks/test behavior context (`main.go:48–74`). Current contribution history stores old/new declaration hashes and credits but replaces older current-version credits (`contribution_history.go:587–643`); all-scope cohort classification uses the latest event (`test_contribution_comparison.go:81–133`). Neither is a surviving-contribution model. Pi omits test definitions (`.pi/extensions/brag.js:158–163`) and accepts only v2 (`239–250`).

## 2. Explicit request and immutable evidence basis

- **Identity required:** explicit selected name/email; no Git-user/session/history inference in the new path. Record raw selection, canonical match key (case-insensitive email), captured alias/identity mappings and their digest, resolution trace, and source of each mapping. Use the existing one-step alias semantics, not silently invented transitive matching (`main.go:553–567`); unresolved/conflicting mappings are explicit errors/uncertainty. Never read identity/config anew halfway through collection.
- Retain commit author, committer and parsed `Co-authored-by` claims separately, including raw and resolved identities, trailer spans and `match_basis: authored|coauthored|both|none`. A trailer is shared-credit evidence, not proof who wrote which line. One event can have multiple contributors but is not counted twice. Approved inclusion policy is authored **or** coauthored matches, explicitly recorded.
- **History scope is independent of target:** `--base REF`, or configured `brag.base` when neither override is given, selects `branch_range` with pinned base commit and merge-base (`merge-base..HEAD`); `--all` selects `head_reachable` (all commits reachable from pinned HEAD). Missing configured boundary asks via actionable CLI error; no upstream/main/master inference or silent widening to all history. Root comparisons use an explicit empty parent; ordinary change events compare one commit to its first parent. Record every parent, not just the compared one.
- **Target defaults to pinned HEAD**, even with a dirty checkout. Only an explicit `tracked_overlay` request includes final tracked index/worktree content; it never attributes those local changes to the selected author. Capture index stage-0 paths and regular-file bytes/modes; reject conflicts/symlink escapes, omit untracked contents. History membership is unchanged by overlay selection.
- Pin refs once. Source references carry commit/tree/blob OIDs **and** SHA-256 of captured bytes; record Git object format. Overlay uses a sorted content manifest `{path,mode,bytes,sha256}` and digest of that manifest, never the existing raw-diff metadata identity (`main.go:636–645`). Its digest describes the captured read set, not an atomic filesystem snapshot or all files if capture is partial. Record manifest completeness, HEAD/index observations before/after and `capture_status: stable_observation|unstable|partial`; detected movement withholds cross-snapshot conclusions. Even unchanged metadata cannot prove absence of concurrent edits.
- Provenance includes contract/method/tool versions, available tool build revision/dirty status (unknown if unavailable), scope boundaries, traversal order/method, streamed commit-ID count/digest and retained evidence commit IDs, target kind/identity, normalized request and limits. A complete traversal does not require every metadata object or commit ID in the rendered document. Repository path references are relative, not host paths. A deterministic serialized raw report has a SHA-256 in its **external envelope**, avoiding a self-referential digest; no timestamps/random IDs are needed in the deterministic payload. Execution remains `not_run`.

## 3. Selected-author-first collection, not a global prefix credited to a person

1. Pin scope boundaries and **stream all scoped commit IDs/identity metadata**, in a documented deterministic traversal order, through bounded scheduling chunks (initially up to 500 commits/request, not 500 commits analyzed). Process each message for coauthor matching, then release its bytes; keep compact matching IDs/parent references and incremental counts/digests. There is **no total-commit or selected-commit count cutoff**. Complete identity discovery establishes exact selected totals before normal diff expansion. If a real object/I/O/time bound prevents completion, keep verified selected records and allow their relevant expansion within remaining budgets, but selected totals remain unknown. No repository-wide metric stage runs first. Selected messages may be retained as evidence details; unmatched messages are not report content unless needed for a specific lineage/context event.
2. Stream changed-path metadata for **every identified selected commit**, then expand test/helper/fixture revisions and relevant author implementation patches/before-and-after blobs, prioritizing current-target test evidence rather than an oldest-history prefix. Other selected implementation changes retain path/commit metadata and explicit source-expansion status; not expanding a source file does not mean it has no tests. Processing an event does not require retaining its entire patch/blob in memory or the payload. Pin Git diff options: no external diff/textconv, no color, zero-context hunks with explicit old/new ranges, no implicit merge flattening. Record binary/mode-only/unreadable/oversize/unsupported changes, not fabricated empty patches. Diff hunks are observations, not behavioral summaries.
3. Enumerate conventional Go `TestX` additions/modifications/deletions and changed test helpers/fixtures across those revisions, preserving compact event/lineage facts independently of retained source details. Mark token stream equal/different/unknown to identify formatting/comment-only candidates, not “material” versus “immaterial.” Also seed existing tests that directly reference a selected-author-modified helper, even if their own declarations did not change; label them `context_change_candidate`, not author-written tests. Any unexpanded, excluded or unreadable relevant source makes the affected event/reverse-reference population unknown; it is not evidence of absent tests.
4. Map each selected event to target candidates. Read bounded intervening **other-author** path history only for those tests, linked helper/fixture/production paths, and Git rename hints. Tag every such record `purpose: lineage|context`, never peer comparison. Preserve each selected contribution event through later edits; do not replace its provenance with the latest declaration editor. Parent blobs or earlier establishing events outside the chosen contribution range may be read only to explain origin/context, labeled `outside_contribution_scope`; they do not become new selected in-scope events. Unknown prior origin stays unknown.
5. Capture target versions of selected-author-changed production paths even when no test link is found, then current test bodies and conservative related context (section 5), including historical context at selected events where available. A missing static test link is not proof of absent tests. No automatic scope widening, blame scan of the whole repository, or fallback into the execution pipeline. A missing/partial lineage remains partial; it does not mean no contribution or a peer-owned test.

Messages and patches may conflict with each other or current code. Keep their evidence identities even when details are omitted; do not make a commit's self-description an authoritative requirement. Deterministic path/ID ordering makes runs reproducible, **not** representative samples. Use bounded in-process buffers and compact state; reread immutable Git objects if needed rather than inventing a persistent/resume cache. Full metadata traversal and relevant-source reads can consume substantial aggregate I/O/time even with low retained memory. These proposals have not been benchmarked and give no full-history completion/runtime guarantee under resource bounds.

## 4. Minimal record shapes and precise states

One envelope, a stable ID-keyed `records` map of retained evidence, and a small population ledger suffice; processed history can exceed that map, with retention omissions accounted for separately. No graph service, plugin framework or new dependency is needed. IDs derive from record kind plus immutable identity (e.g. commit/compared-parent/path/definition hashes), not array position. References use `record_id` plus a source span where needed. Strings below denote field names, not an implemented JSON Schema.

| Record | Required content |
|---|---|
| Envelope | `contract_version`, `method_version`, `provenance` (section 2), `request` (identity/scope/target/coauthor policy), `status`, `populations`, `records`, `authority`, `limits`, `omissions`, `execution: not_run`. |
| Commit | `id`, `oid`, `parent_oids`, `compared_parent` (null only for root), `author`, `committer`, `coauthors`, `match_basis`, `purpose: selected_change|lineage|context`, `message_ref`, `changed_path_refs`, `status`. Keep subject/body/trailer spans as untrusted bytes, with encoding status; invalid UTF-8 uses lossless bounded encoding rather than silently changed text. |
| Source | `id`, `snapshot` (commit or captured-overlay ID), `path`, `blob_oid` (null for overlay), `sha256`, `byte_length`, `mode`, `status`, bounded `content`/`encoding`, retained byte spans. Byte spans are zero-based half-open; display lines are one-based inclusive and derived from those exact bytes. Missing content is never an empty file. |
| File change | `id`, `commit_ref`, `parent_snapshot`, `before_ref`, `after_ref` (null for absent side), `kind: added|modified|deleted|renamed_hint|copied_hint|mode_only|binary`, old/new path, `hunks` (old/new starts/counts and exact diff bytes), `target_ref` (nullable), `target_relation: matched_bytes|changed_bytes|removed|ambiguous|unknown`, `status`, omission reason. Target relation compares path/content evidence, not behavioral equivalence. A rename/copy hint does not establish test lineage. |
| Test event | `id`, `commit_ref`, `change_ref`, package/file/kind/name key, `before_definition_ref`, `after_definition_ref`, `kind: introduced|modified|deleted|context_change_candidate`, `token_relation: equal|different|unknown`, matched author/coauthor refs, `origin: added_at_this_key|preexisting|unknown`, `target_links`. Introduction means added at this key against the recorded parent—not proven first invention anywhere in history. |
| Target test | `id`, target definition/body refs and hashes, package/file/name, `selected_event_refs`, `later_event_refs`, `context_refs`, `test_view`, `build_selection: not_evaluated`, `status`. Multiple selected events can refer to one target test; do not count events as distinct tests. |
| Link/context | `id`, from/to refs, `relation`, `basis: proven_syntactic_binding|heuristic|unresolved`, method and evidence spans, `status`. A proven binding is a resolved source reference, never proof of call reachability, execution or useful behavior. |

Every evidence record has `status: available|partial|unavailable|unsupported`, reasons and applicable omissions. Envelope/phase status is `complete|partial|unavailable`: complete means complete **within the explicitly declared supported population**, never universal behavioral knowledge. Unstable capture makes the envelope partial and target conclusions unavailable. Measured zero is an integer zero only for a complete population; unknown is null, not zero. `not_run` is execution state, not a missing static observation.

Each event's `target_links` carries a candidate target ref (nullable), method, evidence refs and exactly one state:
- `matched`: same unambiguous key and exact declaration bytes; **not** unchanged behavior.
- `changed`: unique same-key descendant with later declaration edits, linked to those events. Retain the selected introduction/modification, but no percentage of today's behavior is assigned to it.
- `removed`: absence established by complete relevant-path/lineage inspection, including disclosed relocation checks; not merely a missing current path.
- `ambiguous`: competing descendants, rename/copy/merge/revert relationships or insufficient identity to choose a unique lineage.
- `unknown`: bounds, unreadable blobs, unsupported syntax or incomplete history prevent a determination.

Git rename similarity, exact-hash relocation and blame are **hints**. Blame surviving lines can support location provenance, not ownership of a function/behavior; formatting can rewrite it and unchanged test lines can depend on changed helpers. Moves/copies may have several candidates; never automatically merge credits. Merges expose all parents, with first-parent delta labeled and resolution-only authorship uncertain. Reverts restoring a hash do not erase intermediate authors or recover earlier credit as sole current ownership. Squash/cherry-pick origin cannot be reconstructed reliably from Git objects; record visible commit claims only, with no causal/original-authorship promise. A bounded search cannot prove a removed test has no semantic replacement.

## 5. Test/implementation/intended-work context

`test_view` contains the full retained declaration ref, source spans for literal inputs/table cases, candidate check predicates and failure calls, explicit error/boundary branches, called-symbol refs and unresolved/dynamic-call markers. Recognition is syntactic and names/signatures are disclosed. Custom assertion helpers and external frameworks may be unresolved; a test body remains inspectable even when no checks are recognized. Never convert assertion counts, table rows or lexical `error` matches into strength/coverage labels.

Follow at most one static call/reference hop initially: locally resolvable Go test helpers and production declarations, plus literal tracked fixture paths. Include relevant package/import declarations, constants and `TestMain`/init context as **potential influences**, not proof they run. Resolve only simple bindings the collector can actually establish; same-name/cross-package/method/interface/dynamic dispatch is heuristic or unresolved without sufficient binding evidence. AST linkage does not imply test-to-behavior adequacy. Reverse helper references are similarly qualified. Read no computed paths, external files, untracked fixtures or credentials; disclose unresolved context rather than execute code to discover it. Retain before/after helper/implementation excerpts when a relevant change is known so an unchanged test hash is not mistaken for stable semantics.

`authority` is always present: `status: provided|absent|conflicting|unreadable`, with refs supplied/authorized by the user to local tracked issue/spec/design/test-plan content, pinned to snapshot/hash/span. Each reference records its **user-assigned role and precedence**, not collector-certified truth. No automatic issue lookup. Commit messages remain separately labeled `intent_clue` even when saying “required.” With authority absent, a model may compare stated intent, implementation and checks but must label intended contract unverified; with conflicting authority it must expose the conflict, not choose silently.

## 6. Proposed bounds, completeness and deterministic omissions

The supervisor-supplied motivating snapshot has **10,608 reachable commits and 6,772 Nick-authored commits**; this revision does not inspect or execute that repository. Refusing it at 10,000/500 commits would defeat the product requirement. Chunk size is scheduling, never population truncation. Enumeration/analysis, compact lineage state, retained raw evidence details and the eventual model payload have separate accounting.

Initial **budget proposals pending measurement at that motivating size**: 256 MiB streamed metadata I/O, 1 GiB expanded source/patch I/O, 64 MiB compact working state and a 5-minute overall deadline; 5s/Git child with cancellation/cleanup. These are starting measurement configurations, not claims that they suffice or approved performance guarantees. In particular, the old 30s/20 MiB proposal is not assumed adequate. Record actual bytes/phase, object reads, processed/retained counts and bound failures; do not benchmark by running repository code. No automatic retries, scope widening or resource-budget escalation.

| Phase/resource | Proposed bounded mechanism and failure behavior |
|---|---|
| Scope/identity discovery | Stream all IDs and metadata in bounded requests, releasing decoded messages. Up to 500 commits/chunk is a scheduling proposal; bound each buffered response to 8 MiB and each message to 64 KiB, checking object sizes before expansion. No aggregate commit-count cap or requirement to retain every message. Oversize/malformed messages make any unresolved coauthor membership unknown; still retain provable author matches and continue later metadata when safe. Incomplete discovery makes selected totals null, not a complete prefix cohort. |
| Selected path/source expansion | Traverse all identified selected commits' changed-path metadata in chunks; no 500-commit/5,000-revision cutoff. Expand relevant test/helper/fixture and implementation blobs incrementally (propose 1 MiB/object), derive compact event facts, and release full bytes. An oversized object/path response or aggregate I/O/time/state ceiling marks affected populations partial/unknown; preserve successfully analyzed author evidence and process later independent work where remaining budgets permit. Whole-tier refusal by selected count is forbidden. |
| Other-author lineage | Stream relevant path events in the same bounded fashion, only for candidate lineage/context. No fixed 2,000-event prefix. Missing intervening revisions invalidate affected lineage certainty even when the current body is available; they do not transfer ownership to a last visible editor. Record first-parent/all-parent uncertainty and whether relevant-path traversal completed. |
| Target and context | Enumerate supported target tests independently of a retained-detail count; no 500-candidate or 2,000-file population cutoff. Parse bounded files incrementally under declared I/O/state/time limits; one context hop, initially retain at most 8 context details/test. Count candidates only when the necessary supported scan completes; otherwise eligible/omitted population counts are null. Excluded/oversized/unexpanded source is disclosed, never counted as no tests. No arbitrary package-wide source dump. |
| Retained/rendered details | Initially retain up to 64 KiB content/source detail, 500 test/event details, 1,000 hunks, 8 MiB serialized raw document. The **500 limit is display/retention only**, not enumeration or analysis. Source/event processing may continue after details fill. Keep referenced compact facts or explicit omission stubs; omit whole details, never cut tokens into misleading “complete” snippets. Prefix messages cannot satisfy coauthor discovery. The later projection has its own explicit byte/token budget. |

On an actual bound failure, keep independently useful available records with exact observed counts and explicit unknown denominators/lineage, not blanket refusal or apparently complete author totals. Identify the failing phase/resource and smallest next option: an **explicitly narrower user-selected scope or larger authorized resource budget**, not silent sampling or automatic continuation. Some relevant current bodies can be available while historical event totals are unknown. Byte/time failures are real partials; elapsed-time-dependent stopping does not become a deterministic population definition.

For each phase/population record `{unit, status, eligible_count, inspected_count, emitted_count, omitted_count, details_truncated, reasons}`. Units are explicit: `scoped_commits`, `selected_commits`, `selected_test_change_events`, `distinct_target_test_candidates`, `relevant_path_events`, `context_records` or `diff_hunks`. Eligible/omitted counts are null when unknown; inspected/emitted are exact observed counts. Counts are not ratios of “quality.” If eligible count is known, omitted = eligible − inspected for analysis omissions; emitted-detail omissions are recorded separately as `detail_omitted_count = inspected − emitted` only for that same unit. Never subtract file counts from test counts.

When a complete population exceeds a detail budget, stable commit-OID/path/byte-offset ordering chooses **display details only**; global completeness and selected-author attribution must not depend on which details fit. At the whole-document cap retain the first fitting whole details in that stable order, reserving the ledger and only the reference stubs needed by retained records; aggregate omission counts/digests can replace per-item stubs for unretained details. Payload size must not turn completed analysis into unavailable author evidence; preserve compact facts and useful current-test details rather than require every processed event in the document. Unretained selected details are explicitly omitted, not silently represented by another author's context. Actual resource failures during source enumeration/parsing instead make relevant populations partial/unknown; they are not merely detail truncation. Compact state itself can hit a real memory bound, so completion is never promised merely because output details are bounded. No extrapolation or implicit equal-difficulty comparison.

## 7. Compact worked example (illustrative, no execution)

In explicit `branch_range B..HEAD`, Ada introduces `TestRejectEmpty` at C1. Peer edits its error-message check at C2; at C3 Peer changes helper `assertRejected` to check only `err != nil`. At HEAD the test declaration equals C2, but helper semantics differ from C1/C2. Simplified records (IDs abbreviated, refs expand to pinned byte spans):

```json
{
  "selected_event": {"id":"e1","commit_ref":"C1","kind":"introduced","origin":"added_at_this_key","after_definition_ref":"test-C1","match_basis":"authored","target_links":[{"target_ref":"t1","state":"changed","evidence_refs":["patch-C2"]}]},
  "target_test": {"id":"t1","definition_ref":"test-HEAD","selected_event_refs":["e1"],"later_event_refs":["e2"],"context_refs":["helper-C1","helper-HEAD","patch-C3"]},
  "later_events": [{"id":"e2","commit_ref":"C2","purpose":"lineage","before_ref":"test-C1","after_ref":"test-C2"},{"id":"e3","commit_ref":"C3","purpose":"context","before_ref":"helper-C2","after_ref":"helper-HEAD"}],
  "authority": {"status":"absent","refs":[]},
  "execution":"not_run"
}
```

Ada's introduction remains linked; Peer is the later editor, not sole contributor. Had C2 left the declaration unchanged, `matched` would still not imply unchanged protection after C3. With body/patch refs a reviewer can observe which oracle was removed and compare current production error handling. “It still checks rejection but may no longer distinguish the intended error” is a **reviewable interpretation**, not a collector fact; without a spec or execution, exact intended behavior, reachability and actual rejection remain unverified. No assertion-count score or behavioral ownership percentage follows.

## 8. Citations, disclosure and semantic review

Raw citations resolve as `{raw_report_sha256, record_id, pointer, snapshot}` plus source hash/path/byte+line span when quoting code. Example raw pointer `/records/t1/context_refs/0` resolves a link, while the cited helper body lives at its referenced source record; merely citing the link does not substantiate a behavioral claim. A projection carries its own version/digest and explicit mappings `{projection_pointer, raw_pointer, raw_report_sha256, snapshot}` for every retained record/span. Array renumbering, snippets, redaction and omitted records must not masquerade as unchanged raw paths; omitted content is not citeable as if present in model input.

Local raw evidence is independently useful without a model. A future projection selects this author-linked evidence, not the current Pi aggregate dashboard. Exactly preview the proposed outbound payload (identities, messages, patches, source/context, authority excerpts and the pinned prompt/request body when a provider path exists), with digest, omission/redaction manifest and no credentials. Provider execution/disclosure requires separate explicit opt-in; preview itself makes no call. Repository text is hostile data in typed fields, never commands or instructions; no tools or automatic source/test follow-up for the model. Test execution requires separate authority, never implied by disclosure approval.

Pointer resolution, source/digest agreement and numeric checks establish reference integrity, **not semantic truth, authoritative requirements or entailment**. Require human-labeled supportability/contradiction/uncertainty fixtures: a resolving citation that contradicts the claim must fail the semantic evaluation, as must “spec says X” citing only a commit message. Include hostile instruction-like messages and helpers whose names promise more than bodies check. A future report separates observation, interpretation and uncertainty; semantic precision needs human review, not another opaque quality number.

## 9. Proposed progression beyond metadata and static acceptance gates

1. With the interface decisions settled, extend the metadata-only method through separately versioned source-evidence record types and deterministic serialization/goldens using standard library only. Keep CLI naming and contract-version dispatch separate from existing commands. Reuse bounded Git object reading (`git_batch.go:30–65,108–169`), scope/identity concepts and test parsing, not repository-wide aggregation or execution setup. No schema/library dependency is necessary for this initial typed contract; stop for approval if a real need arises.
2. Implement explicit request/pinning, selected identity discovery, then selected commit/messages/path-diffs and Go definition events. `contributionCommitMetadata` currently extracts messages (`contribution_history.go:301–320`); `contributionDiffChunk` currently filters test paths and uses raw rename/merge options (`255–294`) and must not be copied unchanged as an implementation-diff contract. Existing `resolveContributionHistory` (`346–643`) is a reference for bounded attribution, not the new traversal policy.
3. Add direct static target/lineage/context reads. Reuse blob/file safety ideas (`engineering.go:255–337`) with context/output limits and captured-content digests. Avoid `trackedHeadContributionVersions`' temporary execution-snapshot dependency (`contribution_history.go:927–942`). Preserve original events alongside later edits. Parse Go comments/build constraints: **if reusing selector inventory, a targeted regression and fix are required first** because `contributionTests` parses with mode 0 (`test_contributions.go:134–137`) but `hasBuildConstraints` examines comments (`mutation_tests.go:428–437`). No repair is authorized by this design document. Record build-conditioned candidates as source evidence with selection not evaluated, not guaranteed runnable tests.
4. Small temporary Git fixtures, **never their programs/tests**, provide cheap goldens: exact alias/coauthor matches; branch versus reachable scope; HEAD versus staged/unstaged overlay and ignored untracked marker; introduction, author modification of a peer's test, deletion and later peer edit; helper-only change affecting an unchanged test; formatting-only candidate; relocation/copy ambiguity; merge/revert/recurring hash; missing authority and message/spec conflict; malformed/build-tagged source and unreadable/symlink input; discovery/detail/context caps and exact/null denominators. Include source scripts, tests and hostile messages that would write a marker if executed; assert it never appears. No automatic retries or external fixtures.
5. Add a counterexample using cheap `git fast-import`: **11,000 reachable commits, 7,000 selected-author commits**, sparse relevant test/helper changes including selected work near the end. With sufficient fixture budgets, assert complete metadata traversal/exact totals, expansion beyond selected commit 500, and the latest author's test event/current context present—not blanket refusal or an oldest-prefix result. Add a 501-target-test variant asserting 501 enumerated/inspected, at most 500 retained details, and truthful detail omissions without marking an excluded source test absent. Mark these scale/full-lane if expensive; do not execute fixture code. Separate low-byte-budget cases must distinguish incomplete metadata (unknown selected total), incomplete source/lineage (unknown affected totals/states), and display-only truncation (complete analyzed totals); each preserves independently available evidence rather than asserting completeness or refusing the whole report.
