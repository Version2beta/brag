## Product conclusion: the existing projection is the wrong primary evidence boundary

The updated requirement is **deterministic collection directly scoped to an explicitly selected author, then model analysis**, prioritizing that author's tests which still matter on the current branch: useful behavior protected, assertion strength, failure/edge coverage, and implementation versus tests versus intended work. Repository metrics must not stand in for person quality.

Current code does something materially narrower and differently ordered:

1. It resolves an explicit identity or falls back to local Git user configuration (`main.go:320–333`), enumerates the entire chosen history (`334–375`), aggregates every contributor, and only then selects that person's totals (`376–405`). `buildEngineeringEvidence` explicitly labels its AST measurements repository-wide and never person-attributed (`engineering.go:157–173`). The selected identity is not a collection filter for those measurements.
2. Static test history counts introduced `TestX` definitions; it does not establish which author-contributed behavior survives today. It scans the oldest bounded prefix of the included ordered history, excludes merges, and reports attempted-commit denominators (`history_tests.go:36–90,238–276`). A deleted test can contribute a historical addition; a modified test is not a newly introduced key.
3. More useful exact-current-version provenance exists in the **opt-in execution pipeline**: definition-change events record commit, old/new declaration hashes, author and coauthor credits (`contribution_history.go:587–643`); current tests must match HEAD, and the latest establishing event—not an earlier recurrence of the same hash—determines current cohorts (`test_contribution_comparison.go:81–133,762–799`). This is a conservative starting point, not an author-quality analysis. A later editor can replace earlier author's whole-declaration credit; it is not surviving-hunk authorship or semantic contribution history. Current existence/hash equality also does not establish continued relevance to the implementation.
4. Commit messages are read for coauthor trailers, not emitted as intent evidence (`history_batch.go:57–84`; `contribution_history.go:301–320,507–517`). The static report shape contains no commit-message records, implementation/test diff hunks, assertions, behavior links, or issue/spec authority (`main.go:48–74`; `engineering.go:85–144`). Pi strips the full history IDs and test definitions, and receives no additional source inspection (section 4 below).

Porting this projection to Go would make the existing repository dashboard more portable, **not satisfy the new requirement**. Do not make mutation/cohort comparison a prerequisite for static author evidence, or treat “selected versus other” detection as a ranking. Preserve the existing CLI defaults/contracts; propose a separately versioned author-evidence path with explicit identity and history/snapshot boundaries. Its collector should start with the selected author's changes, retrieve other history only as needed to establish provenance/current survival and bounded implementation context, and disclose uncertain attribution instead of manufacturing it. The amended plan at the end makes this the first substantive feature.

## 6. Weak measurements, lexical traps, and denominator/cap hazards

These are constraints a future prompt **and deterministic contract** should preserve:

- **Activity/churn:** summed per-commit numstat counts changed lines, not unique/current lines or effort; binary numstat is omitted; combined merge diffs may count no changes (`history_batch.go:137–146`; `main.go:425,600–617`). Source recognition is an extension allowlist, not language analysis (`588–599`). Coauthor parsing is a lexical line scan for `Co-authored-by:`, not proof of individual work (`571–585`), and alias resolution is local/configured. Commit messages are untrusted intent clues, never authoritative requirements.
- **Static AST populations:** no build/type/runtime resolution; generated, vendor or build-inactive source is not uniformly excluded by every static collector. Complexity counts named functions, including test functions, but excludes function literals from enclosing metrics and does not key them separately (`engineering.go:374–385,428–472`). Custom cyclomatic/cognitive thresholds (10/15/4/100), lower-middle median, nearest-rank p95 and top-decile share are defined mechanics, not calibrated quality boundaries (`474–508`). Key changes under moves/renames/splits/merges can masquerade as additions/removals.
- **Test inventory:** conventional top-level declarations with exact Go testing signatures, no receiver/type parameters/results; not arbitrary frameworks, fuzz targets, runtime table rows or all helper assertions (`engineering.go:625–669,684–758`). `t.Run` count is a lexical parameter-name selector match. A range + composite literal + Run anywhere in one function marks “table-driven”; it does not establish data flow between them (`760–782`). Full declaration hashes change on formatting/signature/body edits; stable hashes can miss changed helper/fixture/implementation semantics. No assertion-strength analysis exists.
- **Static introduction history:** oldest 500 included commits, 100 changed test files/commit, 5,000 file revisions and 20 MiB blobs; merges excluded and limits/read/parse/metadata failures mark partial (`history_tests.go:18–45,85–90,276`). `all_tests_added_ratio` denominator is **attempted included commits**, including attempts whose definitions were not attributable; status/reason and analyzed/omitted counts must travel with it (`238–276`). Do not substitute all reachable commits or selected-author commit count. Selected-additions denominator is introduced TestX definitions in the measured bounded history, not all current tests.
- **Selector-inventory source defect (static finding, not separately reproduced):** `contributionTests` parses with mode `0` and then calls `hasBuildConstraints` (`test_contributions.go:134–137`), but that helper inspects `f.Comments` (`mutation_tests.go:428–437`). Without `parser.ParseComments`, the intended build-constraint exclusion is ineffective here. Build-excluded test declarations can enter eligible counts and later produce missing-selector/inconclusive outcomes. Mutation candidate parsing does request comments (`mutation_tests.go:309–318`), so do not generalize its exclusion guarantee to test inventory. The selector inventory also silently skips parse failures/nested/ignored/platform paths (`test_contributions.go:111–137`) rather than exposing a full rejected-test population ledger. Passing current tests does not establish completeness of that denominator; add a focused fixture before relying on it in a new static author contract. No code/test correction was made.
- **Current contribution provenance:** full supplied ordered history in 500-commit chunks, 8 MiB changed-path output/chunk / 32 MiB aggregate; 100 relevant paths/commit, 5,000 relevant revisions, 20 MiB blobs, 50,000 events, 32 MiB cached historical module metadata, and bounded author/commit metadata (`contribution_history.go:15–21,155–224,374–395,452–481,532–604`). Current-candidate path filtering is not selected-author-only collection. Relevant merges, renames, nested-module identity gaps and any cap/error withhold current credits; current worktree changes are not retroactively credited (`435–447,639–643`; `test_contribution_comparison.go:764–799`). Latest exact-definition credit is not original/surviving-hunk authorship or causal ownership.
- **Documentation/generation:** only comment presence, recognized extensions/patterns and content hashes; generated-marker search is limited to 4 KiB, otherwise generation is unknown (`docs_evidence.go:14,80–81,279–304`). No truth/quality test of prose, and no generator run.
- **Architecture/security:** module-prefix import classification and limited `go.mod` parsing, no resolved dependencies, replace/build-tag/nested-module ambiguities (`architecture_security.go:98–99,129–183,297–323`). Import aliases/selectors are syntactic, not type-checked bindings, so shadowing or similarly named methods can mislead. Any `.Handle`/`.HandleFunc` also gets a heuristic registration indicator independent of package (`667–690`). Auth matching lowercases/removes `_`/`-` and substring-matches `authorization`, `authenticate`, `authorize`, `authn`, `authz`, `credential`, `password`, `passwd`, `token`, `permission`, `privilege`, `role`, `accesscontrol`, `acl` (`771–778`): false positives such as ordinary parser tokens and unrelated identifiers are expected. Importing weak crypto is not proof it is used unsafely.
- **Execution samples:** mutation operator `brag-go-mutation-v1` swaps comparison/logical/boolean tokens; boolean reference resolution is restricted, many paths/platform/build populations excluded, scan capped at 10,000 candidates, lowest stable IDs selected (20 default / 50 max), not representative package/operator sampling (`mutation_tests.go:27–29,250–383,820–832`). Equivalent or irrelevant mutants can survive; a kill is not a real defect or causal author impact. v4 score is killed/(killed+survived), excluding invalid/inconclusive/not-executed; preserve it as existing bounded experimental evidence, never a composite person score (`955–957`).
- **Contribution samples:** branch population cap 200, pair matrix 1,000 shared across current/baseline; all comparison cap 200 across both cohorts, at most 500 pairs each (`test_contributions.go:320–345`; `test_contribution_comparison.go:12–13,800–875`). Current all-comparison tests are package/cohort-stratified but mutations remain lowest-ID and package relevance is not matched. Pair omissions use selected tests × selected mutation IDs; mutation omissions are separate. Per-cohort denominators can differ; v7 intersection fixes that comparison boundary, not confounding by package relevance, responsibilities or difficulty. Shared/unattributed tests are not peers. Missing, failing-control, unstable, timed-out, unexecuted and artifact-incomplete outcomes are not survivors (`233–345,348–418`). Set-derived uniqueness/marginals are not remove-test suite experiments (`test_contributions.go:592–595,657–778`).

**Shared static bounds:** 2,000 Go files, 1 MiB/file, 20 MiB/snapshot; 100 changed-function details, 500 test definition details, 50 parse-failure paths; 500 document files / 100 changed-document details; 500 architecture package details / 20,000 import specs; 500 security locations (`engineering.go:20–23,160,563,677–680`; `docs_evidence.go:81`; `architecture_security.go:14–16,99,567`). Detail truncation can coexist with complete aggregate counts; input omission/parse failure can make the population incomplete. The model must not equate these. Unavailable, unsupported, partial, failed, not_run/not_executed, measured zero, and zero-denominator null are distinct. Citation resolution alone detects none of these semantic misreadings.

## 7. Feasibility of a second language

Git scope/identity/churn and bounded document-file changes are reusable; recognized non-Go extensions already contribute to source churn and unsupported-population disclosure. **Go analysis is spread across the package**, not behind an adapter: AST/parser/token imports in `engineering.go`, `history_tests.go`, `docs_evidence.go`, `architecture_security.go`, `mutation_tests.go`, and `test_contributions.go`; Go testing signatures/package IDs and selectors are embedded in static and execution paths (sections 2 and 6). Merely adding an extension to `source()` would not add analysis.

A bounded static second-language slice is feasible after separating snapshot transport and author provenance from Go parsing. It needs explicit parser/dependency approval (this project currently has no dependencies), language-specific declaration/test identity and hashing, assertion/behavior-context extraction, import/module rules, test framework coverage and unsupported statuses, stable snapshot/source references, schema/projection changes and fixtures for malformed/oversize/build-conditional files. Do not reuse `brag-go-ast-v2` thresholds or Go `TestX` semantics as universal measures. JavaScript/TypeScript would require decisions about syntax/parser and multiple test styles; Python would require import/test-style handling. No language choice or parser has been approved here.

Start with **static author-attributed current test/diff evidence**, which advances the product goal even without a new complexity score. Language-neutral records should identify source spans/provenance/status; language-specific collectors explain how they located them. Dynamic tests, coverage event adapters and mutation operators are separate, much larger extensions requiring explicit execution authority, host/snapshot/cleanup controls and their own evidence denominators. Mark those unsupported initially rather than pretending Go runners generalize safely. No second-language code or dependency was added.
